# 更新时间候选：范围与验证

**MCP 0.5.0 迁移开发中，尚不可交付，不要启用自动发送。** 本文适用于 Windows 独立版的固定日报模块，不适用于尚未迁移的 Project Workbench 插件；Windows 打包及真实端到端尚未验收。

## 默认快速采集

普通诊断和日报通过固定官方 endpoint `https://open.teambition.com/api/mcp/v2`，
调用只读 MCP `teambition.project.task-query`。`tql` 为
`updated >= '<报告起点的 Asia/Shanghai ISO 8601 时间>'`，不再把候选下界
前移 24 小时。若起点含小数秒，仅向下取整到秒，保守放宽不足 1 秒。
不添加结束上界，因此截止后再次更新的任务仍是候选。

逐页读取全部返回候选，校验组织/项目、归档、更新时间和身份，再逐候选读取
详情及全部动态页。完成后以相同条件完整分页重列候选；新增或变化任务重读，
退出当前集合的条目移除，最多三轮仍不稳定即阻断。服务端拒绝查询或返回低于
下界的任务时中止，不回退旧 App API，不静默降级为全项目扫描。本机校验无法
证明服务器没有漏返回候选。

最终日报仍只按动态 `createTime` 使用原有 `[开始, 结束)` 时间窗。
候选范围与最终报告窗口是两件事；小数秒取整不改变日报窗口，不因读到旧活动
就提前停止动态分页。`selection` 内保留的 `q` 是旧格式兼容字段，实际 MCP
调用使用 `tql`，不是继续调用旧 v3 App 路由。

## 完整分页与预算

候选任务和活动须完整分页；其 `nextPageToken` 必须存在，只有已验证的空字符串
才结束，缺失字段不能当末页。空页带非空游标仍继续。任务/活动的相同 ID/内容
去重但仍计入返回行预算，同 ID 不同内容、跨任务绑定或无效包络阻断。

项目列表采用不同的专用合同：`structuredContent` 含非空字符串 `requestId`
及 `result` 数组，无 `code`/`errorCode`；存在的 `nextPageToken` 必须为非空
字符串并继续，字段缺失是实测观察到的结束形态，不能套用于任务/活动。
列表固定 `sort=updated:desc`，以不同页大小双遍扫描并核对 ID 与返回内容；
重复项目记录或扫描结果漂移阻断。
只列当前账号参与的可见非归档项目，双遍一致也不保证完整或原子快照；找不到
项目时可以手动填写已核实的项目/组织 ID，再进行相同来源核验。

`nextPageToken` 是不透明游标，**重复值不等于完成，也不能仅因重复就宣布
读完**。不能用项目去重掩盖重复记录，也不能因达到预算就假装取得末页。

握手、初始化通知、工具目录、业务调用及重试均计入原有请求和响应预算。
项目、批次或整次预算耗尽、未取得相应工具合同的结束形态，或项目双遍核对
失败时，均阻断摘要和发送，
不得截断后生成部分日报，也不能当作零更新。完整预算与加密进度规则见
[采集与内容规则](../DATA_COLLECTION_CONTRACT.md)。

## 完整性边界与全项目复核

有些活动可能不会推进任务 `updated`，权限变化也可能改变可见范围。
旧任务的新动态若未进入下界，快速模式可能漏掉；所有返回行校验通过也不能
证明历史全量无遗漏。候选合同保留 `activity_updated_index_guaranteed=false`、
`historical_event_coverage=false` 和 `snapshot_guaranteed=false`。
`candidate_overlap_seconds` 在整秒起点为 0，只有上述不足 1 秒的取整余量，
不再是 86400。

不按更新时间排除旧任务时，显式使用
`Client.collect(..., candidate_mode="full_project")`。原生“详细诊断导出…”
使用该复核方式，可能较慢，不调用模型或发送钉钉。即使完整遍历当前项目，
也受权限、归档选项、资源预算及非原子分页限制，不能恢复已删除、不可见、
已移出项目的任务或历史成员关系。快速与全项目模式的进度互不复用；旧 App
或旧 24 小时候选策略的临时进度不能冒充当前 MCP 采集。原有历史、配置、
加密凭据和发送账本保留，旧 App 加密值不用于连接或回退。

## 已验证合同与尚待验收

获授权的只读实测确认了非空 `teambition.project.task-query` 和
`teambition.task.activity` 的分页成功标记、末页游标及任务 `isArchived`
布尔类型；`teambition.task.query` 的 `result` 为单元素数组，不含通用 `code`。
生产默认路径已按这三个工具分别接入合同验证器，不以 HTTP 200、JSON-RPC
成功或空列表代替业务验证。

`project.query` 的 `my=true` 列表已获授权只读实测，HTTP 200 下观察到上述
项目专用响应包络及缺失末页游标形态，并已接入项目专用验证器。固定
`sort=updated:desc` 下两种页大小的扫描 ID 集合一致，只证明观察到的集合
相符，不能证明目录无遗漏。实现采用固定排序双遍扫描及重复/漂移阻断，
不扩大账号参与、当前可见和非归档范围，也不保证非原子分页的快照完整性。

状态完成语义仍未实测，不能凭状态名称或当前 `isDone` 推断解决状态。
成员及当前状态名称只能解析 MCP 已返回且校验通过的字段，未解析项和
来源冲突继续阻断。Windows 打包及真实程序端到端尚未验收。

运行 `python -m unittest discover -s tests -v` 做离线回归。虚构测试覆盖
非空/空分页、单任务无 `code`、归档布尔、起点等号、UTC 等价时间、截止后
更新、完整分页及预算阻断。合成测试不请求真实项目、OpenAI 或钉钉；不把
真实 UserToken、响应正文、成员或任务数据写入开发文件。旧 HTTP `q` 路径
的模拟请求数不代表当前 MCP 性能，不能沿用为速度结论。

以上局部只读合同和合成回归不等于 Windows 打包或真实日报端到端验收，
也不保证每种动态都会推进 `updated`。采集、筛选、校验和格式固定执行；
仅有实质评论需要归纳时调用 OpenAI，零更新不调用。当前分支保持自动发送
关闭，不以手工改核验标记代替尚缺证据。
