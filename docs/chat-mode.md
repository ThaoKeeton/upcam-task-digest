# 独立版聊天模式（开发中）

聊天位于 Windows 独立版左侧的“聊天”，与固定日报分开。它使用已保存的企业、项目、归档范围、MCP 授权和 OpenAI 配置；不会更改日报时间、筛选、定时或发送规则。此分支仍须完成 Windows 构建、目标机验收与真实接口验证，不能因本文假定功能已发布。

## 数据与查询范围

- 每条问题交给所选 OpenAI 模型理解并形成只读查询计划。必要时模型还会收到与问题有关的查询结果、先前回答等上下文用于理解或整理；选择显示原始结果只表示不再调用模型进行本轮整理，问题本身仍会发给 OpenAI。
- 当程序识别到本轮明确要求完全不使用 OpenAI，或不向其发送项目内容时，会停止该轮并提示，而不发起模型或 MCP 请求。
- 程序请求 `store=false`，这不保证服务商零留存。相关任务标题、评论、姓名、ID 等业务内容可能进入 OpenAI；本机已知凭据泄漏检查不能识别所有手工写入的秘密。模型可能出错，请核对关键内容。
- 任务及动态查询只针对已保存的当前项目，不自动沿用日报的额外视图筛选；项目列表可列出当前账户可见项目。当前版本不支持从聊天临时切换任务查询项目，也不下载附件或打开链接。
- 名称搜索仅匹配任务标题中的文字，不能当作负责人或评论作者筛选；摘要会列出实际检索条件。
- 查询采用固定的只读能力，不提供项目写入、任意 MCP 工具、自由 TQL、任意 URL 或模型直接发送。请求和来源内容均受本地范围、分页、时间和体积限制；超限或校验失败会停止，不截断后冒称完整。
- 项目动态按起点筛选当前更新时间较新的可见任务，再核对匹配任务的动态时间。若动态未推进任务更新时间可能遗漏；已删除、不可见或移出项目的历史及原子快照也无法保证。一次最多读取 20 个匹配任务的动态；范围过大时请指定任务或缩短时间。
- 上下文只在本机内存中维护最近六轮。单条回答过长时不带入后续对话并给出提示；退出程序清除会话。OpenAI 仍按其服务条款处理收到的请求和数据。

## 发送到钉钉

每条回答只生成本机临时草稿，模型不能发消息。可以在聊天中要求“发送上一条”；请核对预览内容，确认后才会发送。用户点击“预览并发送到钉钉”，检查完整内容和当前已保存的机器人，明确确认后才发送。聊天发送不沿用日报配置的 @ 名单，不自动提醒成员。新问题、清空会话、配置变化或发送尝试会使旧草稿失效。

发送前本机持久记录请求和内容的哈希；钉钉确认不等于群成员已阅读。超时、断线或响应不明时不能自动重试，先检查钉钉。对已结束但结果未知的记录，聊天页先显示该次记录编号、发送时间、内容短哈希和机器人标识；如果本次运行内存在哈希完全匹配的答复，会显示原文供核对；重启后应用不保留正文，无法确定是哪条消息时应取消。用户核对后可明确解除这条记录的阻断，仅允许未来新消息，不会自动重发旧内容。如果确认期间记录或机器人改变，解除会被拒绝。仍在发送或中断后无法确认已结束的记录不能在此解除；不要删除或重建共享发送账本来绕过保护。同一机器人 URL 的参数顺序和临时签名变化不会绕过阻断；如果机器人令牌被更换，程序无法仅凭新令牌确认仍是同一机器人。以上保证依赖同一份完整、可验证的本机持久账本，不等于远端恰好送达一次。

开发和自动测试只使用虚构数据、模拟模型与机器人，不使用或输出真实凭据，也不发送真实 webhook。
