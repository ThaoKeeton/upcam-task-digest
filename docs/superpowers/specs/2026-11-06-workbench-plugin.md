# Native project-workbench digest plugin

## Goal and boundaries

Provide real WinUI pages to `project-workbench` while preserving standalone UPCAM Task Digest 0.4.3 and its Python business rules. Do not embed a desktop window, migrate secrets to host JSON, invoke real services during development, or modify the platform or DingTalk repositories. Use synthetic installation, lifecycle, recovery and parity tests.

## Verified platform contract

Reference commit: `ThaoKeeton/project-workbench@6565180b17130f6d494978291df4138de3fdb0b4`, branch `feat/native-plugin-workbench`, API 1, .NET 10, Microsoft.WindowsAppSDK `1.8.260921001`. The unmodified, Git-blob-verified reference snapshot lives under `integrations/project-workbench/reference`; source provenance is recorded in `source-manifest.json`. It is a build/test input, never a private runtime dependency shipped with the plugin.

Register code-created `WinUiView` factories during `IWorkbenchPlugin.InitializeAsync`. Factories create new controls on the host UI thread. State belongs to the plugin instance. The host shares its SDK and WinUI assemblies; the plugin package excludes copies. No plugin XAML/PRI is supported. The existing standalone uses .NET 8 and a different Windows App SDK, so its window assembly cannot be reused.

The inspected SDK has no post-activation callback, process supervision, host preference API or window-handle API. Initialization must not schedule network work before the host commits activation. Until a public activation hook is available, the first page/command opens the backend and starts the already-authorized scheduler. This limitation is visible; do not simulate an activation callback using delays or reflection. Stop/lifetime cancellation owns resource cleanup. Normal installation retains the host's explicit package-trust gate.

## Architecture and fixed interfaces

- Plugin: `plugins/UPCAM.Workbench`, namespace `Upcam.Workbench`, class `DigestPlugin`, manifest ID `com.upcam.task-digest`, version `0.1.0`, host minimum `0.1.0`, API 1. Plain WinUI controls; no nested `Window`, no WebView. Main digest and settings views use compact local tabs and retain draft state across factory recreation.
- Backend entry: `plugin_worker_entry.py`; adapter: `upcam_app/plugin_worker.py`. Preserve `worker_entry.py` defaults. Invoke with `--data-directory <absolute local path>` and optional `--synthetic` only in an explicit acceptance build. Never infer a user profile when the path is absent.
- Transport: existing UTF-8 newline JSON envelopes `{id,op,payload}` and `{id,ok,result|error}`. First operation `plugin_handshake`, payload `{protocol_version:1,backend_version:"0.4.3",nonce:<32 lowercase hex>}`; response repeats those fields plus `mode:"project-workbench"`, `data_directory`, `synthetic`, and `ruleset_revision`. Reject mismatches before initialization or other operations. Request cap 2 MiB, response cap 32 MiB, strict response correlation and encoding. Child stderr is drained and discarded.
- C# process interface: `PluginWorkerClient.StartAsync(string packageDirectory,string dataDirectory,bool synthetic,CancellationToken)` returns an initialized client after handshake; `SendAsync(string operation,JsonObject? payload,CancellationToken)` returns the worker result; `DisposeAsync()` ends only its owned process tree. Client errors have safe fixed text and never echo protocol lines or stderr. Deadlines: 30 seconds ordinary operations; 125 minutes collection operations. Timeouts/cancellation break the connection, kill the child, and never replay a request automatically. Native Windows Job Object kills the worker on host death. A shutdown request is bounded and cleanup still runs if the lifetime token is already cancelled.
- Profile: default `<context.DataDirectory>/profile`. Explicitly selecting an existing standalone data folder binds to that same canonical folder, not a copied history/ledger. Host settings hold only the directory binding. Reject roots, relative/UNC paths, links/reparse components and non-profile adoption. Credentials remain Windows-user DPAPI; settings/cache/history/ledger formats remain unchanged. A named singleton `Local\\UPCAMTaskDigest.Singleton.v1` covers the whole backend session, matching standalone 0.4.3. Profile switch stops the current worker before opening another profile and preserves data on failure. Disabling the plugin releases the singleton after worker exit, allowing standalone rollback.
- Plugin backend allows business operations but rejects standalone update/preferences operations. Saves preserve all standalone UI/startup preferences; no registry/startup changes. `auto_send_enabled` cannot become true merely by importing/adopting data. Existing validated authorization may resume after activation. No automatic catch-up beyond existing core rules.
- UI: native overview/manual range/diagnostics/sample preview/send/history; settings for local secrets, project/read-only discovery, mappings (JSON/TSV), model cache/reasoning/Fast, mentions, collection budget, schedules, and automatic sending. Buttons call the same validated Python operations. No editable template. Business settings are saved by explicit action; missing mapping/collection integrity still blocks sends. Password boxes never display saved secrets. Host controls global language/theme/tray/autostart; standalone settings remain preserved for rollback.

## Test and delivery contract

Use fresh explicit synthetic profiles for service parity, credentials, history, schedule ledger, lease contention, interrupted send recovery and profile restoration. No real credentials, external API or send in tests. Build an unpacked plugin package with its own private Python worker; do not bundle host SDK/.NET/WinUI DLLs. Validate install, trust, enable, native view factories, commands, disable, restart restoration, path-with-spaces, cancellation/timeouts and child cleanup with the actual pinned SDK/Core on Windows. A dedicated acceptance host is not evidence of a complete production host UI test; state the exact boundary. Preserve standalone 0.4.3 artifact and build project. Report platform interface gaps and any unavailable Windows validation truthfully.
