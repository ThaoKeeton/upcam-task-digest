# UPCAM 0.1.1 / Workbench 0.4.0 shipping-pair QA

This job already lives under `shipping-pairing` in `.github/workflows/workbench-plugin.yml`. It is not a passed Windows result until that job succeeds, and it is not a stable release.

The job consumes the production plugin already built by `windows-native` on the same workflow (plugin 0.1.1, backend 0.4.6). It does not rebuild the host and does not pin an older production artifact.

The pinned host is the actual artifact from Workbench commit 655d7b6496067daad7c5e4cefb1f1da1b8379536, run 42518602297, artifact 13633291911. The downloaded archive is hash-checked in PowerShell 7. The driver then checks the EXE and App DLL with `Read-Sha256` before UI Automation. A legacy `Get-FileHash` expression remains only as a sanitized probe: Windows PowerShell 5.1 has failed that expression, and the probe cannot pass or fail `exactShippingHostBytes`. `test-hash-helper.ps1` runs under Windows PowerShell 5.1 first and does not open the host. The loaded Core DLL is hash-checked by the tiny installer, which is compiled against the shipping Core DLL, not copied host sources. It performs `PluginPackageStore.InstallAsync` on the audited production folder, verifies every installed file's bytes and disabled/untrusted/unloaded state, then exits. The unchanged shipping EXE opens normally. Its owned window is accepted only after the fresh Default workspace title is exactly `Default · Project Workbench`; the vendored reference host uses a different title and is not this pair. UI Automation then handles native trust, enable, page and backend, no-project diagnostic rejection, disable/re-enable, and graceful close with owned worker cleanup. Saved automatic sending must stay off.

A separate fresh runner is required because the existing complete-reference-host UI test already creates `%LOCALAPPDATA%/ProjectWorkbench`. This test refuses an existing profile. Do not remove that profile or weaken the gate to fit the same job. Windows PowerShell 5.1/STA is used for native UIA, PowerShell 7 for orchestration.

No real service credentials, project IDs, data, provider calls, OpenAI calls, Webhook or DingTalk sends are involved. No existing profile is read or removed. No task cancellation during real collection is claimed: the unconfigured diagnostic rejects before collection. Cancel-disabled after rejection and lifecycle cleanup are checked; synthetic transport cancellation remains separate evidence. Native folder-picker installation is not exercised; the actual shipping PackageStore is.

The upstream UIA process ownership, clean host environment, fresh root, symlink rejection, fixed/sanitized selector diagnostics, and bounded job-object cleanup are retained. Evidence includes input identities, PackageStore result, UIA report and an owned unconfigured window screenshot. Success must include all checks and `cleanup: graceful`.

The public cross-repository Actions artifact download uses the job's temporary GitHub token. If GitHub rejects that token's artifact access, stop and report that access error. Do not add a secret, weaken authorization, rebuild and call it the same binary, or silently switch host versions. A separately authorized artifact-transfer route would then be needed.
