# UPCAM 站会日报 · Workbench 原生插件

插件版本 0.1.0，业务核心为独立版 0.4.3。此插件向统一窗口提供真正的 WinUI 页面，不会嵌入或启动另一个日报应用窗口。独立版 0.4.3 继续保留。

## 兼容范围

目前针对 `project-workbench` 的 `feat/native-plugin-workbench` 分支、host 0.2.0 / API 1 开发，锁定已实现运行服务的源码提交 `d2005d469aef6a385c134b6914fb6dfa9cff20b2`。宿主使用 .NET 10 / Windows App SDK 1.8.260921001；独立版原有的 .NET 8 / 其他 WinUI 运行库不应复制到宿主插件目录。

`reference/` 是同一项目所有者授权使用的原始 SDK、Core 和测试宿主源码快照；`source-manifest.json` 记录每个文件的原始 Git blob。它用于离线构建和验证，不是要再次安装到宿主的运行库，也不表示新增了未经核实的第三方许可证。

## 安装与首次使用

1. 完整解压正式插件 ZIP。选择其中的 `com.upcam.task-digest` 文件夹，而不是 `worker` 文件夹。
2. 在兼容工作台的“插件”页点击“从本地文件夹安装”，选择该目录。安装只复制文件；插件默认未启用。查看来源并通过工作台原有的信任流程启用插件。
3. 打开“UPCAM Task Digest”或对应设置页面，连接本机无窗口业务进程。新安装默认使用工作台为插件分配的数据目录，不会自动查找、读取旧版密钥。
4. 首次配置在插件设置页完成，保存后的项目范围仍需实际只读核验。配置迁移不会代替真实项目核验、扩大自动发送权限，或绕过缺失映射与采集完整性检查。

正式包名称含 `production`；名称含 `acceptance` 的包只用于 CI 虚构数据验收，页面会明确显示测试标识，不应用于真实项目。

## 接续独立版数据与回退

先完全退出独立版，再在插件的数据目录设置中指定原有独立版数据文件夹。接续绑定的是原目录，配置、Windows 当前用户 DPAPI 凭据、模型缓存、运行记录、采集进度和发送账本继续共用；不会生成可独立调度的副本。路径必须是本机绝对目录，不能是网络目录、链接或磁盘根目录。

同一登录会话使用与独立版一致的互斥标识，避免两者同时运行。用户若要回退，先停用插件或完全退出工作台，等待业务进程结束，然后启动保留的独立版 0.4.3。接续原目录后，后续记录仍在原处。上述回退针对接续原目录；新建的宿主默认目录不会自动迁入独立版 0.4.3，不要复制出第二套可调度账本。不要在另一账户或另一电脑上复制 DPAPI 文件来尝试解密，也不要让其他旧进程绕过互斥标识运行。

独立版的开机启动、托盘、语言、主题和更新偏好保留在原配置中；插件不会修改注册表或替工作台设置全局偏好。使用插件时，窗口、托盘、开机启动和工作台本体更新由宿主管理。切换运行方式后，请使用宿主或独立版现有界面选择唯一的日常启动入口。

## 由宿主管理自动运行

插件通过实际 `IPluginRuntimeContext.BackgroundTasks` 注册唯一的 `digest-scheduler` 任务。安装、信任、启用或打开页面本身不会启动定时采集；初始任务停止，启动恢复默认关闭。保存明确开启的自动发送配置，或在插件原生页面启动任务时，仍先执行原有业务校验。页面切换不会结束已启动任务；停止、停用和宿主退出由实际生命周期处理。

需要开机后恢复时，在插件内明确开启宿主启动恢复选项。恢复仅对仍被信任的同一插件包、同一数据目录和相同已授权业务配置生效；项目、凭据或计划发生变化时会停止并提示重新保存，不会静默扩大范围。成功恢复不依赖先打开日报页面。平台的全局后台管理界面可能仍在开发，插件自身提供启动、停止和恢复设置。

业务 API 密钥继续由原目录的 Windows 当前用户 DPAPI 保存，作为 Python 核心和独立版回退的唯一凭据来源。不会自动搬入或双写到宿主保险库。宿主 `Secrets` 仅保存程序生成的恢复范围校验密钥；设置 JSON 只保存非敏感绑定校验信息，不保存它的值。恢复校验不能替代业务范围、模型和发送账本校验。

工作台开机自启由平台负责，本插件不会创建系统计划任务或修改注册表。执行仍需要电脑已开机、账户已登录、宿主已启动、联网且未休眠。沿用核心已有的恢复窗口和防重规则，不无限追发历史日报。

## 取消、超时与未知发送结果

普通操作有 30 秒期限，采集类操作和可能触发项目只读采集的保存操作最多 125 分钟。取消、超时或协议损坏会断开并终止插件自己拥有的业务进程，不自动重放请求。自动任务故障不会在内部循环重启连接；恢复必须再次通过已有授权与账本核验。特别是发送中断时，消息可能已经发出：重新连接后应查看运行记录，原有未知发送结果防护继续有效。只有显式操作才会重新连接；插件不会循环重启并盲目重试发送。

## Windows 构建与验证

在 Windows 上安装 Python 3.12、`requirements-build.txt` 和匹配的 .NET 10 SDK：

```powershell
python -m unittest discover -s tests -v
pwsh -File integrations/project-workbench/build-plugin.ps1 -BuildAcceptance
```

生成的正式包位于 `dist/workbench-plugin/`。`plugin-package.json` 及 ZIP 旁的 SHA-256 用于发现构建或传输错误，**不是独立可信的发布者签名**。宿主仍应执行自身的包审查和信任检查；本插件没有自动下载或替换宿主/插件的更新器。

Windows CI 另外运行进程故障测试和基于真实锁定 SDK/Core 的原生验收宿主，结果以报告中列明的检查为准。此验收宿主不能替代用户最终安装电脑、真实项目权限、钉钉客户端展示或未测试的新宿主版本验证。所有开发验收只使用虚构数据，不填真实密钥，不发送钉钉。
