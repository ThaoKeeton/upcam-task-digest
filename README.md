## 启动与开发验收

下载成功 Windows 工作流的 **UPCAMTaskDigest-WinUI3-windows-x64** artifact，完整解压 ZIP，运行 `UPCAMTaskDigest.exe`。保留 DLL 和 `worker` 子文件夹。新版采用 C#、XAML、WinUI 3 / Windows App SDK 和 WinUIEx，参考 PowerToys 原生设置窗口。完整升级及操作说明见 [WINUI_APP.md](WINUI_APP.md)。

## MCP 连接与验证边界

官方 endpoint 固定为 `https://open.teambition.com/api/mcp/v2`，不接受自定义地址或重定向。个人 UserToken 只由当前 Windows 用户 DPAPI 加密保存在本机；首次连接前必须确认本机授权，提示会披露 Token 将发送给 Teambition 官方服务、应用的只读用途及 Token 泄露可能带来的账号权限风险。仅保存 Token 不等于允许连接，也不等于启用自动发送。更换 Token 需要重新授权和核验。旧 App ID/Secret 加密值仅为保留原数据而留存，绝不用于连接或回退。

已获授权的只读实测确认了非空 `project.task-query` 与 `task.activity` 的分页成功标记、末页游标和任务 `isArchived` 布尔类型；`task.query` 的 `result` 为单元素数组，不能假定存在通用 `code`。独立版默认采集已按这三个工具分别接入明确的合同验证器；虚构回归覆盖非空/空分页、归档布尔和单任务无 `code` 的流程。这不等于真实端到端或发布验收。`project.query` 的 `my=true` 项目列表也已获授权只读实测并接入项目专用合同：HTTP 200 响应的 `structuredContent` 含字符串 `requestId` 和 `result` 数组，无 `code`/`errorCode`；非空游标表示后续页，观察到的末页缺少 `nextPageToken`。固定 `sort=updated:desc` 下两种页大小的扫描 ID 集合一致，但这不能证明列表完整。实现以固定排序、不同页大小扫描两遍，核对项目 ID 与返回内容；重复项目记录或扫描漂移阻断。列表仅限当前账号参与的可见非归档项目，仍可能遗漏且不是原子快照。状态完成语义未实测，不据当前名称或完成标记推断历史解决事件。独立版将窗口内原始活动交给模型分类，未知动作本身不再构成语义阻断；模型判断仍需复核。Windows 打包及真实程序端到端尚未验收。

真实 Token、原始项目响应和真实任务/成员数据不得写入仓库、测试样例或开发文件；本轮文档和离线回归只使用虚构值。原有本机配置、加密进度和用户主动选择的诊断导出仍按下文受控保留规则处理。

指定项目查询以 `projectId` 单独请求，不附加 `pageSize` 或 `pageToken`；`my=true` 项目列表仍按原有分页和双遍核对。一次获授权只读样本中，单项目结果为含一项对象的 `result` 数组，带字符串 `requestId`、无 `nextPageToken`，项目 id 与请求一致，并提供名称、组织与布尔归档字段；遇到意外非空游标会停止，不猜测下一页。该单样本不能证明其他账号或版本的响应形态。

## 首次配置（开发验证流程）

1. 在“账户与模型 → Teambition”顶部的“1. MCP Token 与连接授权”先填个人 UserToken，点击“保存配置并确认 MCP 授权”并确认权限提示，无需先填写项目。钉钉机器人 Webhook/签名密钥和 OpenAI API Key 仍各自保存在本机；只读连接与诊断不需要后二者。
2. 再在下方“2. 加载并选择项目”点击“加载我的项目”，以固定排序完成两遍项目扫描并核对结果，选中项目后从已验证返回字段填入组织 ID 及可选编号前缀。列表仅包含当前账号参与的可见非归档项目；重复项目记录、扫描漂移或预算耗尽时阻断且不改当前项目。双遍一致仍可能遗漏，不是完整项目目录；找不到时可手动输入已核实的 Organization ID 和 Project ID，再进行相同来源核验。
3. 在“项目范围”选择含任务动态的时间窗并保存配置，程序按当前来源进行只读核验。成员姓名和当前状态名称仅从 MCP 已返回且已校验的 ID/名称字段解析；缺项标记“未解析”。旧映射保留为高级可选覆盖，不补造姓名，不把名称或当前 `isDone` 当成状态完成语义。来源身份、筛选字段、时间或完整分页无法核验时阻断；未知动作和富文本交给模型整理。缺少已核实解决集合或明确事件证据时，不应分类为已解决。
4. 点击“刷新当前 Key 可用模型”。模型列表只在手动刷新时请求；成功结果按当前 Key 在本机缓存，刷新失败保留旧缓存。选择模型、reasoning effort 和 API 服务等级；默认是 `gpt-6-luna` / `max` / 标准费用，需要当前 Key 权限支持。
5. “自动运行”页保留时间及“每批采集任务数（1–700）”设置，默认每批 300，并非项目总数限制。**本分支保持自动发送关闭**，不得用开启自动运行绕过尚未完成的合同或 Windows 验证。
6. “授权并只读测试连接”、项目核验和只读诊断均不调用 OpenAI、不发钉钉。成功仅证明对应检查通过，不替代 Windows 端到端验收。租户、项目、归档、筛选条件或 Token 变化后重新核验。

默认调度是上午 08:50 和下午 16:50。上午采集前一日 16:50 到当日 08:50；下午采集当日 00:00 到 16:50，均使用电脑本机时间。自动执行仅在桌面应用运行且电脑未休眠时工作。应用重开后会补跑最近 24 小时内、且自动执行已启用期间错过的时段，并使用该时段原定采集窗口；启用前或超过 24 小时的时段跳过。已有记录（包括阻断或发送结果不明）不会重跑，避免重复发送。可选当前用户登录启动，启动后在系统托盘运行；只有电脑开机、该用户已登录且联网时才可运行。

每次外部请求前，程序先持久化请求、最大响应字节和返回行的预留预算，收到完整响应后原子结算。中断时无法确认的响应保留预占，避免重启获得额外额度；预算计数不等同于已确认业务动态数量。

## 自动日报流程

应用先在本机确定项目、视图字段与归档范围，完整读取候选任务详情和活动页，再按固定半开区间 `[开始, 结束)` 选择动态。匹配任务的完整原始任务对象及每条窗口内活动交给 OpenAI Responses API，包括未知动作、富文本、引用、链接预览及附件引用，不作本地语义剥离。原始字段可能包含任务/成员/引用 ID、姓名、URL 和业务正文，发送前应确认这些项目内容适合交给所选 OpenAI 账户。附件和链接的实际内容不下载、不读取。所有源字段均明确作为不可信数据，不是模型可执行的指令；请求使用结构化 JSON 输出和 `store=false`。

已知本机凭据（含凭据 URL 中的令牌）泄漏会在请求/发送前阻断，不通过删掉字段继续；检测不能保证识别人工写入的所有秘密。完整 UTF-8 JSON 模型请求（含规则、输出 schema 和源数据）上限为 **256 KiB**，超限明确失败，不截断或省略任务/活动，目前尚不支持更大项目的模型分批。采集批次与模型批次不同，采集成功不保证请求能装入此上限。普通运行历史保存生成日报或安全诊断，不保存原始任务/评论/活动响应；短期加密采集进度及用户主动选择的详细诊断另受各自保留规则约束。

桌面普通采集通过固定 MCP 工具，以 `updated >= 报告起点` 筛选候选，再读取每个候选的详情及全部动态页；不设结束上界，窗口后再次更新的任务仍会检查。动态 `createTime` 决定最终半开窗口。候选下界不再前移 24 小时。尚无每种动态都推进 `updated` 的保证；更新时间未推进、权限变化或当前不可见的任务可能漏项，不能宣称完整历史覆盖。“详细诊断导出…”保留全项目历史复核，不按更新时间排除任务，不调用模型或发钉钉。

候选任务和活动须完整分页，只有已验证的空末页游标才结束；项目列表另按专用合同处理观察到的末页字段缺失，并以固定排序双遍核对。MCP 不透明游标即使重复也不表示完成；项目列表中的重复项目记录或漂移、页数预算耗尽或分页不完整均阻断，双遍一致也不保证项目目录完整。采集按批推进，单次最多 10,000 个返回任务；每批保留原有请求、分页、记录、响应大小和时长预算。整次采集还受 50,000 次请求尝试、1,000,000 条返回记录、512 MiB 响应、128 MiB 保留 JSON 和两小时（含进度缓存年龄）的限制，最多三轮来源重核。超过任一限制会阻断摘要与发送，不截断任务或分页，也不能当成零更新。普通模式的列表查询使用更新时间下界；额外本机字段筛选不减少列表请求。详细诊断仍需全项目复核。

只有完整读取任务详情及全部动态页后，才将该任务存入短期加密进度。取消、断电或中断保留未完成进度，自本次采集开始最多两小时；恢复必须匹配来源、冻结时间窗、采集策略与 Teambition 凭据身份，并重新完整列出候选，刷新变更或新增任务、移除失效条目。每轮结束再次核对候选集合与版本，最多三轮仍不稳定就阻断；成功后清除进度。自动运行页的“清除未完成的采集进度”无需确认，只清临时缓存，保留设置、凭据、历史和发送防重账本，不改变自动发送授权与防重行为。

当前候选范围内没有窗口动态且完整翻页与一致性检查通过时，程序直接按仓库格式输出标题、实际时间范围和“📊 更新 0 项”，不调用 OpenAI。任何非空窗口活动集都会交给模型，包括纯状态变化或仅附件引用。分页不完整、范围/身份冲突或无效时间仍阻断，不能当成“无动态”；零更新仅指本次可见候选，不证明历史上没有活动。

仅附件评论和未知富文本不再经过旧评论适配器拦截，原始引用/结构随活动送给模型。模型不得从文件名、URL 或元数据推断未读取内容，也不得声称读取了附件；没有实质进展时允许空摘要。保留的 Workbench/兼容管线仍使用旧评论适配规则，其“仅正文送模型”和未知结构阻断行为不代表独立版。

正式日报头部显示实际上海时间窗口，使用“🕒 时间范围”和“📊 更新”。标题为“项目编号 完整原标题”，保留原有冒号等标点。编号读取真实 `uniqueId`，前缀使用 API 的 `project.uniqueIdPrefix` 或本机已确认设置；缺失会阻断正式报告与发送，不从提交消息猜编号。在“项目范围 → 任务编号与链接”可设置前缀和当前项目“全部”视图链接；留空视图时使用官方任务直达路由。更换企业或项目会清除旧显示设置，避免混用。

分类与摘要由 OpenAI 按仓库规则生成：明确的窗口内解决状态迁移且窗口末未重开优先，其次实质进展、新建和其他；当前任务状态仅作上下文。摘要聚焦进展、问题、结论、风险、阻塞、下一步和明确的交接/交付事实，无补充可为空。程序验证任务结果完整性、允许类别、格式和来源绑定，并从原始任务字段组装标题、链接、当前状态与负责人，发送前重建核对。**这些检查不证明模型理解正确，分类和摘要必须复核**；通知不能自动当成真实提交、代码作者、合并或解决的证据。

遇到来源或请求阻断，先点“只读诊断”，再点“复制诊断文字”取得范围、数量和失败原因。只读诊断不调用模型，也不验证模型结果或 256 KiB 请求是否可生成。可选 v5 脱敏结构保留旧适配器的动作指纹、有限标记分类及字段形状，供离线定位；“未知”只表示旧适配器未识别，不是独立版语义阻断。原始评论不进入诊断文字或脱敏结构；详细边界见 [DIAGNOSTICS.md](DIAGNOSTICS.md)。

需要保留实际动作和项目正文排查时，可选“详细诊断导出…”。确认内容说明并选择本机文件夹后，程序只读采集一次，将所需任务与窗口内动态写入独立 JSON；过滤本机配置凭据及已识别的认证字段，不通过界面通信返回正文。采集进度遵循上述加密和到期清理规则。文件可能仍含业务隐私或人工写入的未识别秘密，请只私下分享，不放进仓库或公开日志。该模式不调用 OpenAI、不发送钉钉，也不解除原有阻断。

以下为需保留的既有发送规则，**本迁移分支不得启用自动发送**。现有程序没有逐次人工审核门禁；通过技术校验后可发送到设置的钉钉机器人，但技术校验不能保证 AI 分类和摘要正确。完成 Windows 与真实端到端验收并复核结果前，不得据此启用自动发送。手动再次点击发送会重新采集并发送同一时间范围，无额外确认弹窗；每次手动命令有独立请求 ID，同一请求不会发送两次。定时任务仍按企业、项目、报告日期、窗口及接收目标防重。所有发送均先持久化占位；已有进行中或结果不明的尝试会阻断后续发送，不会自动盲目重试。原有账本和运行历史保留，不通过删除记录放开重发。

## 钉钉指定成员艾特

在“账户与模型 → 钉钉”选择手机号或钉钉 userId，填写群成员标识（每行一个，也支持中英文逗号、分号或空格），不加 `@`，最多 50 人，再保存本机配置。留空保持原消息；清空并保存即可关闭。不要填写姓名、员工编号或 Teambition 成员 ID。

应用按所选类型生成 `atMobiles` 或 `atUserIds`，并在发送消息末尾添加对应 `@标识`，按原有空段格式与正文分隔，不加分割线，不会艾特所有人。名单只保存在本机设置，不发给 OpenAI，也不加入诊断导出或运行历史正文。原始标识会进入钉钉消息，不能保证所有客户端都替换为姓名；只有群内成员可被匹配，本机检查仅验证格式，不发送测试消息或核实成员身份。误填已保存或新输入的密钥、Webhook 令牌等认证信息时，保存和发送均会被拦截，错误不回显原值。

接口依据：[自定义机器人消息类型](https://open.dingtalk.com/document/orgapp/custom-bot-send-message-type)、[自定义机器人发送群消息](https://open.dingtalk.com/document/development/custom-robots-send-group-messages)。本机支持手机号为 6–20 位数字（可有一个前置 `+`），userId 为 1–128 位 ASCII 字母、数字、点、下划线或连字符；这些是应用的保守输入范围，不宣称是钉钉全部标识格式。

## OpenAI 模型和 Fast

`/v1/models` 只返回 API Key 可见的模型 ID 等基础元数据，不保证 Responses 端点权限，也不提供 reasoning effort。应用仅为内置官方资料已核验的模型显示 reasoning 档位；其他模型只提供 `default`。`gpt-6-luna` 的 `max` 档位在当前应用资料中已核验。模型列表中的模型仍可能因账户权限或项目设置而无法生成 Responses。

API 快速服务等级与 ChatGPT/Codex 界面里的快速模式设置是两回事。应用通过 Responses API 请求参数 `service_tier=fast` 显式启用 Fast；当前官方模型定价资料列出 `gpt-6-luna`、`gpt-6-astra`、`gpt-6.1-sol`、`gpt-6.1-terra` 的 Fast 档。Fast 默认关闭；它按 token 收取高于标准处理的费用、速度提升不保证，且是否可用仍受账户、地区、模型和项目权限限制。标准模式会显式发送 `service_tier=default`，因此不会继承 API 项目级 Fast 默认。Fast 请求若被 API 拒绝，本次日报会阻断，不会发送。

OpenAI 文档：[`/v1/models`](https://developers.openai.com/api/reference/resources/models/methods/list)、[reasoning effort](https://developers.openai.com/api/docs/guides/reasoning)、[Fast mode](https://developers.openai.com/api/docs/guides/fast-mode)、[Fast mode 定价](https://developers.openai.com/api/docs/pricing?latest-pricing=fast)、[Responses `service_tier`](https://developers.openai.com/api/reference/resources/responses/methods/create)。`store=false` 不等同于零保留；请查看[数据控制说明](https://developers.openai.com/api/docs/guides/your-data)了解 API 的默认滥用监控留存和账户策略。

## 数据范围与边界

- 默认通过 MCP 服务端 `updated >= 报告起点` 预选，窗口后再次更新不排除；最终仍用动态 `createTime` 筛选原有半开时间窗。默认不含归档，用户归档选项保持不变。全量复核使用 `candidate_mode="full_project"`，原生详细诊断已使用该模式。快速与全量合同及缓存隔离见 [采集规则](DATA_COLLECTION_CONTRACT.md)。
- 采集按批恢复并在每轮结束重列任务，刷新可见版本或成员集合变化；最多三轮仍变化就停止。短期缓存不是历史快照：API 不保证每次动态都改变任务 `updated`，也不保证分页游标形成原子快照。无法保证已删除、已不可见、已移出项目任务或历史项目成员关系的覆盖。超出项目、批次或整次预算都会阻断，不能当成零更新。
- 独立版把匹配任务的原始对象及全部窗口内活动交给用户选择的 OpenAI API 模型；包括原始 ID、富文本、引用和附件元数据，不下载附件。`store=false` 可避免 Responses API 常规存储，但不能代替账户侧数据保留设置。
- Windows 版支持系统托盘、关闭窗口时隐藏和托盘菜单显式退出；可选择当前用户登录时启动并以托盘模式运行。该开关只写入当前用户的 Run 项，不需要管理员权限。关机、休眠、用户未登录或断网期间不会运行。
- 本应用不在后台上传运行历史、映射或模板更新；更新日报规则需打包并发布兼容的新程序版本。
- `manual_review.py` 和对应测试保留为仓库已有的离线分析工具，不是桌面应用发送流程的审核门禁。
